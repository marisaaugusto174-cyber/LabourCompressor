# CSV 格式要求

本文档定义当前项目在 `CSV` 场景下的**输入格式**与**输出格式**要求。  
目标是保证：

- 程序能稳定读取
- 回写结果位置固定
- 测试数据与正式数据格式一致

## 1. 适用范围

当前规范适用于以下流程：

- 表格导入
- 按链接下载视频
- 模型打标
- 标签结果回写
- 归档前索引记录
- 结构化标签回表

当前实现基于：

- 第一列读取 URL
- 自动识别“是否存在表头”
- 若存在结构化列，则优先回填结构化列

## 2. 输入 CSV 要求

### 2.1 文件编码

- 推荐使用：`UTF-8`
- 文件扩展名：`.csv`
- 分隔符：英文逗号 `,`

### 2.2 最小必填要求

输入 CSV 至少需要满足以下条件：

- 至少有 `1` 条非空数据行
- 第一列必须是待处理的媒体链接
- 链接必须是完整 URL，示例：
  - `https://www.bilibili.com/video/BV...`
  - `https://www.youtube.com/watch?v=...`
  - `https://www.douyin.com/video/...`

### 2.3 允许的输入形态

当前程序支持两种形态。

#### 形态 A：有表头

示例：

```csv
url,title,remark
https://www.bilibili.com/video/BV1xxx,示例视频,测试
https://www.bilibili.com/video/BV2xxx,示例视频2,测试
```

规则：

- 第一行作为表头
- 第一列仍然必须放 URL
- 表头名不强制必须叫 `url`
- 当前主流程按**第一列位置**读取，不按表头名定位

#### 形态 B：无表头

示例：

```csv
https://www.bilibili.com/video/BV1xxx,示例视频,测试
https://www.bilibili.com/video/BV2xxx,示例视频2,测试
```

规则：

- 如果第一行第一列看起来就是 URL，程序会判定为“无表头”
- 如果第一整行都是空值，也会判定为“无表头”
- 无表头模式下，程序内部会给列生成临时列名：
  - `column_1`
  - `column_2`
  - `column_3`
  - ...

### 2.4 推荐输入模板

推荐统一使用以下格式，减少歧义：

```csv
url,title,remark
https://www.bilibili.com/video/BV1xxx,视频标题A,可选备注
https://www.bilibili.com/video/BV2xxx,视频标题B,可选备注
```

原因：

- 可读性更好
- 人工排查更方便
- 回写后结构更稳定

## 3. 输入字段规则

### 3.1 第一列：URL

- 必须放在第一列
- 不能为空
- 程序当前只读取第一列作为任务 URL
- 若某行第一列为空，该行会被跳过，不进入下载任务

### 3.2 其他列

- 允许存在
- 当前会原样保留
- 程序不会依赖它们来决定下载和打标逻辑

可用于存放：

- 标题
- 备注
- 来源说明
- 批次编号
- 人工校验结果

## 4. 输出 CSV 要求

### 4.1 回写方式

程序存在两种回写模式。

#### 模式 A：结构化列模式（推荐）

如果 CSV 含有以下列名：

- `归档状态`
- `一级标签`
- `二级标签`
- `三级标签`
- `四级标签`
- `归档路径`
- `归档文件名`

则程序优先按这些列回写。

结构化回写规则：

- `一级标签 / 二级标签 / 三级标签 / 四级标签` 保存正式接受的多分支标签结果
- 为防止分支归属丢失，每个值必须带 `0级标签` 前缀
  - 例：`核心动作: 跑动 | 内容领域: 日常生活 | 主体对象: 人物`
- 新 V0.3 任务的 `核心动作/主动作` 允许写回表格，但在归档层只保留唯一一条完整路径
- `归档路径` 只能反映这条唯一合法 `核心动作/主动作` 路径
- `归档文件名` 保存最终归档文件名

说明：

- `xlsx` 中，`归档文件名` 会被写成指向归档后源文件的可点击超链接
- `csv` 不支持富链接，`归档文件名` 在 `csv` 中只保存纯文本文件名

#### 模式 B：单列汇总模式（兼容旧表）

如果结构化列不存在，程序会在原 CSV 基础上新增一列：

- 默认列名：`accepted_tags`

如果该列已存在：

- 程序会覆盖对应行的该列内容

如果该列不存在：

- 程序会自动追加该列

### 4.2 单列汇总模式的回写值格式

当一条素材命中多个标签时，当前回写格式为：

```text
标签路径1 | 标签路径2 | 标签路径3
```

分隔符固定为：

- 空格 + 竖线 + 空格，即 ` | `

示例：

```text
核心动作 > 身体动作 > 位移动作 > 跑动 | 内容领域 > 人物生活 > 日常生活
```

### 4.3 无表头 CSV 的回写行为

如果输入 CSV 原本没有表头：

- 程序会先自动补一行表头
- 原数据行号会顺延
- 第一列表头会变成：
  - `column_1`
  - `column_2`
  - ...
- 若没有结构化列，最后新增：
  - `accepted_tags`

示例：

原始输入：

```csv
https://www.bilibili.com/video/BV1xxx,示例A
```

回写后可能变成：

```csv
column_1,column_2,accepted_tags
https://www.bilibili.com/video/BV1xxx,示例A,动作标签库 > 音乐与乐器 > singing
```

## 5. 推荐正式输出结构

如果要作为正式生产表格使用，建议从一开始就采用以下列结构：

```csv
url,title,remark,归档状态,一级标签,二级标签,三级标签,四级标签,归档路径,归档文件名
https://www.bilibili.com/video/BV1xxx,视频标题A,测试批次A,,,,,,,
https://www.bilibili.com/video/BV2xxx,视频标题B,测试批次A,,,,,,,
```

说明：

- 正式表建议使用结构化列，而不是只保留 `accepted_tags`
- 程序运行后会同时回填：
  - `归档状态`
  - `一级标签`
  - `二级标签`
  - `三级标签`
  - `四级标签`
  - `归档路径`
  - `归档文件名`

## 6. 禁止事项

以下写法当前不建议使用：

- 不要把 URL 放在第二列或后续列
- 不要在第一列写相对路径或文件名代替 URL
- 不要混用中英文分隔符
- 不要在同一文件里同时混合“部分有表头、部分无表头”的结构
- 不要把唯一合法 `核心动作/主动作` 之外的分支误当成新 V0.3 归档路径来源
- 不要把多分支标签拆成多套重复列，当前程序按固定四级结构回写

## 7. 当前实现限制

这是当前版本必须明确知道的限制：

### 7.1 URL 识别规则

当前主流程按**第一列位置**读取 URL。  
即使表头写了 `url`，如果 URL 不在第一列，也不会按该列名自动寻找。

### 7.2 结构化列与归档路径的关系

- 结构化列可以包含多个 `0级标签` 分支
- 新 V0.3 任务的 `归档路径` 只消费唯一合法 `核心动作/主动作` 路径；V0.1、V0.2 和已持久化历史显式内容路径继续兼容
- 如果没有结构化列，程序才会退回单列 `accepted_tags` 模式

当前回写只写：

- `accepted_tags`

还没有拆成以下更细粒度列：

- `candidate_tags`
- `rejected_tags`
- `download_status`
- `archive_path`
- `model_provider`
- `taxonomy_version`

### 7.3 适用于当前版本，不等于最终长期格式

这份规范是**当前实现对应的稳定格式**。  
后续如果你要进入正式生产阶段，我建议再升级成更完整的任务表结构。

## 8. 当前推荐结论

如果你现在要新建一份 CSV，请直接用这个模板：

```csv
url,title,remark,归档状态,一级标签,二级标签,三级标签,四级标签,归档路径,归档文件名
https://www.bilibili.com/video/BV1xxx,样本A,测试,,,,,,,
https://www.bilibili.com/video/BV2xxx,样本B,测试,,,,,,,
```

这是当前正式结构化表格最稳的写法。  
如果必须兼容旧流程，才退回单列 `accepted_tags`。
