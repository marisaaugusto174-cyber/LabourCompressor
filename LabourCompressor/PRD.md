## 2. 产品定义

`LabourCompressor` 是一个本地优先、规则约束型的媒体资产采集、剪辑、打标、回表、归档工作流系统。

它不是单一下载器，也不是单一模型打标工具。它的核心价值是把以下链路变成可重复执行、可回溯、可中断、可继续的本地流程：

1. 导入采集表格
2. 按 URL 批量下载视频
3. 自动分割长视频为可入库片段
4. 对片段视频做视频级模型打标
5. 按标签库合法化结果
6. 多分支回填表格
7. 新 V0.3 任务按唯一合法 `核心动作/主动作` 完整路径归档
8. 同步写入程序内 `xlsx` 总表
9. 导出失败 CSV

产品的核心资产是：

- `V0 标签库`
- `提示词库`
- `结构化表格记录`
- `视频归档库`
- `任务状态与失败原因`
- `平台凭证与模型配置`

## 3. 当前阶段目标

### 3.1 V0.5.1 目标

V0.5.1 聚焦把自动分割做成默认主线，重点不是继续扩散功能，而是让用户能够在 Web UI 中一键完成完整任务。

当前目标是让用户在 Web UI 中完成：平台凭证配置、模型 API 配置、导入表格、Preflight、下载、自动分割、片段视频打标、回表归档、结果查看和失败导出。

V0.5.1 的验收链路固定为：`一键启动 -> 导入表格 -> Preflight -> 下载 -> 自动分割 -> 片段级视频打标 -> 回表归档 -> 失败导出`。

V0.2 手动 `AfterEdit` 流程保留为高级兼容模式，不再作为默认验收链路。

### 3.2 当前非目标

当前阶段不做：云端账号系统、多人协作权限、远程素材传输、自动浏览器登录抓取 cookies、自动去水印承诺、完整训练数据交付平台、复杂 BI 报表、全平台下载稳定性承诺。

## 4. 目标用户

### 4.1 主用户

负责素材采集、人工剪辑、标签归档的本地操作人员。

用户特点：不应被要求理解 CLI 参数；需要拖拽或选择本地表格；需要清楚知道任务卡在哪一步；需要失败后知道下一步该处理什么；需要在人工剪辑后继续同一批任务。

### 4.2 管理用户

负责维护标签库、提示词库、模型配置、平台凭证、总表格式和归档规则的人员。

---

## 5. 标准工作流

### 5.1 一键全流程主线

1. 用户打开本地 Web UI
2. 用户选择或拖入任务表格
3. 用户确认模型档位与平台凭证
4. 用户运行 `Preflight`
5. 用户启动一键全流程
6. 系统读取 URL 行
7. 系统跳过 `已归档 / 已下载未归档 / 已下载待剪辑` 行
8. 系统按平台自动选择下载凭证
9. 系统下载视频并自动合并
10. 系统按标准规则重命名下载文件
11. 系统创建 `下载缓存目录/AfterEdit` 和 `下载缓存目录/ProblemClips`
12. 系统自动分割为合法计算区间 `5-60s`、推荐区间 `5-30s` 的片段
13. 合法片段进入片段级打标，问题片段写入失败状态

### 5.2 高级兼容：人工剪辑阶段

1. 用户关闭自动分割并启用人工剪辑闸门
2. 用户在本地剪辑下载后的视频
3. 用户导出剪辑后文件
4. 导出文件放入 `下载缓存目录/AfterEdit`
5. 文件名必须遵守标准命名规则

标准文件名：`原视频标题_视频下载分辨率_下载年月日_视频时长秒数.mp4`

示例：`刷短视频现状_720P_260426_000027.mp4`

允许字符：中文、英文大小写、数字、`_`、文件扩展名中的 `.`。

### 5.3 片段打标归档

1. 系统扫描自动分割后的 `AfterEdit` 片段
2. 系统生成 `AfterEdit_归档记录表.xlsx`
3. 系统校验片段文件名、重复项和文件存在性
4. 系统对片段视频做标准压缩缓存
5. 系统调用视频模型做视频级打标
6. 系统合法化候选标签
7. 系统多分支回填表格
8. 新 V0.3 任务按唯一合法 `核心动作/主动作` 完整路径归档
9. 系统同步写入程序内总表
10. 失败项进入失败 CSV 导出

## 6. 表格要求

### 6.1 正式输出表格

正式完整能力标准为 `xlsx`。

标准列：

- `URL` 或 `文件名`
- `采集人`
- `归档状态`
- `一级标签`
- `二级标签`
- `三级标签`
- `四级标签`
- `归档路径`
- `归档文件名`
- `失败信息`

### 6.2 用户上传表格

支持：

- `xlsx`
- `csv`
- `Numbers`

边界：`xlsx` 支持完整写回与本地文件超链接；`Numbers` 只做读取兼容，检测到后按现有 xlsx 内容抽取能力读取；`csv` 只保留导入和失败导出，不承诺正式写回、格式和超链接。所有中间表、回表、归档记录仍统一写 `xlsx`。

### 6.3 程序内总表

程序内总表固定为 `xlsx`，作为完整能力承载表。

要求：写回目标固定为 `both`；用户表与程序内总表同时回填；总表按 URL 或文件名做 upsert；`归档文件名` 在 `xlsx` 中应为可点击本地文件链接。

## 7. 下载需求

### 7.1 支持平台

当前 V0.5.1 下载仍以 `yt-dlp + ffmpeg` 为主，不承诺覆盖率；新增下载失败统计口径，为未来扩平台提供依据。

当前下载凭证层覆盖：

- `Bilibili`
- `YouTube`
- `抖音`
- `TikTok`

下载主引擎：

- `yt-dlp`
- `ffmpeg`

### 7.2 平台凭证

系统必须按平台维护下载凭证。

每个平台支持 `cookies.txt` 和 `cookies-from-browser`。

凭证优先级：

1. 平台级 `cookiesFilePath`
2. 平台级 `cookiesFromBrowser`
3. 全局 cookies 兼容回退

边界：系统不承诺自动浏览器登录抓取 cookies，不承诺绕过平台风控，不承诺自动去水印，不在日志、报告、测试输出或错误信息中打印真实 cookies、API key、token。

多平台下载成功率受平台策略、账号状态、cookies 新鲜度、`yt-dlp` 支持状态和本地网络环境影响；V0.5.1 只承诺边界清晰、失败可分类、下一步建议可读。

### 7.3 下载状态

下载失败必须被分类为用户可理解的状态。

至少包括：缺少平台下载凭证、Cookies 需要重新获取、Cookies 已过期、平台风控拦截、平台请求过频、下载文件重命名失败、未识别到下载产物、合并失败。

### 7.4 下载幂等

系统必须避免重复下载。

规则：`已归档 / 已下载未归档 / 已下载待剪辑` 行跳过；标准化文件名已存在时复用，不视为失败；同一 URL 重跑时以状态列和已有产物为准。

## 8. 视频打标需求

### 8.1 视频级检测

正式视频打标必须使用模型原生视频理解能力。

禁止把抽帧图片理解作为正式默认链路。抽帧只允许用于调试、实验或显式降级。

### 8.2 视频压缩缓存

送模前必须创建标准化压缩缓存。

当前 profile：

- `360p`
- 保持原始帧率
- 视频 `H.264 650 kbps`
- 音频 `AAC 64 kbps`
- 容器 `mp4`
- 按源文件哈希复用

若压缩后仍超过模型上传安全阈值，必须明确失败，不静默改为抽帧。

### 8.3 模型候选池

Web UI 显示产品名，内部映射实际 API model id。

当前候选：

- `Qwen3.7Plus` -> `qwen3.7-plus`
- `Qwen3.6Flash` -> `qwen3.6-flash`
- `Gemini 3.5 Flash` -> `gemini-3.5-flash`

默认顺序：

1. `Qwen3.7Plus`
2. `Qwen3.6Flash`
3. `Gemini 3.5 Flash`

约束：

- `GPT-5.4` 当前不进入视频候选池
- Provider API Key 通过 Web UI 配置
- Preflight 必须验证当前选中模型可连通
- 自动打标并发由 Web UI 滑块控制，范围 `1-64`；默认值分别为 `16 / 24 / 4`

## 9. 标签与归档规则

### 9.1 标签库

V0 标签库已经固化为程序内 taxonomy。

标签机制要求：

- 模型输出只能作为候选
- 正式标签必须通过标签库合法化
- 正式记录必须绑定标签库版本
- 非法标签不得回表或归档

### 9.2 多分支回填

识别层允许多分支标签并存。

回表规则：`一级标签 / 二级标签 / 三级标签 / 四级标签` 承载结构化标签；同一级多标签使用固定分隔符写入同一单元格；回填内容必须带 0 级标签前缀，避免分支归属丢失。新 V0.3 任务只在归档目录选择时要求唯一合法 `核心动作/主动作`，次动作与其他已接受标签继续回表。

示例：

```text
核心动作: 跑动 | 内容领域: 日常生活 | 主体对象: 人物
```

### 9.3 唯一核心动作主动作归档

新 V0.3 任务归档层只消费唯一合法 `核心动作/主动作`。

规则：每个视频只能保留唯一一条合法 `核心动作/主动作` 完整路径用于归档；次动作和其他分支不得参与目录选择；归档根目录固定为 `视频数据归档库/<完整核心动作路径>`；文件最终只能落入一个目录位置。V0.1、V0.2 和已持久化的历史显式内容路径继续兼容，不自动迁移。

## 10. Web UI 需求

### 10.1 页面原则

Web UI 面向操作人员，不暴露底层技术参数。

默认不展示：

- 下载模式
- 合并模式
- 打标模式
- prompt 路径
- 原始日志

这些内容可以保留在调试折叠区。

### 10.2 必备控件

用户可见控件：

- 用户表路径
- taxonomy preset
- 打标模型
- 自动打标并发数
- 归档根目录
- 配置模型 API
- 配置下载凭证
- 运行 Preflight
- 一键全流程启动
- 生成 AfterEdit 表格
- 导出失败 CSV

### 10.3 状态壳层

任务状态区必须显示：

- 任务状态
- 当前环节
- 当前文件
- 进度
- 当前模型
- 来源模式
- 当前平台
- 下一步操作

结果列表采用卡片式展示。

成功项显示：

- 行号
- 当前/最终阶段
- 归档路径

失败项显示：

- 失败类型
- 简短原因
- 下一步处理建议

## 11. AfterEdit 要求

### 11.1 自动建目录

开始下载任务时，系统必须创建：

```text
下载缓存目录/AfterEdit
```

### 11.2 生成记录表

用户点击 `生成 AfterEdit 表格` 后，系统必须：

- 扫描 `AfterEdit`
- 读取支持的视频文件
- 按顺序写入第一列
- 第一行第一列固定为 `文件名`
- 生成标准 `xlsx`
- 自动把该表载入用户表路径

默认输出：

```text
下载缓存目录/AfterEdit/AfterEdit_归档记录表.xlsx
```

### 11.3 文件校验

第二阶段启动前必须校验：

- 文件名是否符合标准命名规则
- 是否存在重复文件名
- 表格中登记的文件是否存在于 `AfterEdit`

发现异常时：

- 阻断进入打标
- 回填失败状态
- 回填 `失败信息`

---

## 12. Preflight 要求

Preflight 是正式运行前的本地体检，不启动下载、打标或归档。

必须检查：

- 用户表可读
- taxonomy 可读
- prompt library 可读
- 下载目录可写
- 归档根目录可写
- `yt-dlp` 可用
- `ffmpeg` 可用
- 当前模型 provider 可连通
- 当前模型支持视频输入

任何失败都必须阻断正式启动。
