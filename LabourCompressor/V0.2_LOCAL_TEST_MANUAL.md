# V0.2 本地测试手册

本文档记录当前已跑通的本地 Web 流程，用于后续复测和问题定位。

适用范围：

- 平台 URL 下载监测
- 人工剪辑后的 `AfterEdit` 二阶段回表
- 模型打标
- 内容题材归档
- 结果回写与任务历史恢复

## 1. 启动方式

在项目根目录启动 Web UI：

```bash
npm run web
```

默认访问地址：

```text
http://127.0.0.1:4311
```

如果页面打不开，先检查端口是否已有旧进程占用：

```bash
lsof -ti tcp:4311
```

## 2. 测试前准备

### 2.1 表格

正式测试优先使用 `.numbers` 或 `.xlsx` 总表。

下载监测表至少需要：

- `URL`
- `采集人`
- `归档状态`

剪辑后回表使用系统生成的 `AfterEdit_归档记录表.xlsx`，表头为：

- `文件名`
- `相对路径`
- `原始文件名`
- `来源URL`
- `归档状态`
- `一级标签`
- `二级标签`
- `三级标签`
- `四级标签`
- `归档路径`
- `归档文件名`
- `失败信息`

### 2.2 下载凭证

下载凭证配置文件：

```text
config/download-platform-credentials.local.json
```

支持平台：

- `bilibili`
- `youtube`
- `douyin`
- `tiktok`

凭证优先级：

1. 平台级 `cookiesFilePath`
2. 平台级 `cookiesFromBrowser`
3. 请求级 `cookiesFilePath`
4. 请求级 `cookiesFromBrowser`
5. 全局 `global.cookiesFilePath`
6. 全局 `global.cookiesFromBrowser`

建议：

- Bilibili、抖音、TikTok 优先使用平台级 `cookiesFilePath`。
- YouTube 只有遇到登录限制、年龄限制或格式限制时再补 cookies。

### 2.3 模型凭证

模型凭证配置文件：

```text
config/model-providers/providers.local.json
```

Web UI 中选择的是产品名，内部会映射到 provider 和 model id。

当前候选模型：

- `Qwen 3.6 Flash`
- `Qwen 3.6 Plus`
- `Qwen 3.5 Plus`
- `Gemini 3 Flash Thinking`
- `Gemini 3 Pro`

注意：

- `Gemini 3 Flash Thinking` 固定使用 thinking 配置。
- Preflight 会区分未启用、key/额度问题、模型不支持视频、连通失败。
- 不要在日志、截图或 issue 中粘贴真实 API key。

## 3. 推荐测试流程

### 3.1 第一阶段：下载监测

1. 打开 Web UI。
2. 选择总表。
3. 选择下载缓存目录。
4. 确认模型和下载凭证已经配置。
5. 启动下载任务。
6. 下载完成后，系统只更新下载监测表的下载状态和失败原因。

预期状态：

- 成功下载并等待人工剪辑：`已下载待剪辑`
- 已经归档：`已归档`
- 下载失败：`下载失败`

重跑规则：

- `已归档` 不会重复下载。
- `已下载待剪辑` 不会重复下载。
- `已下载未归档` 不会重复下载。
- `已跳过：视频过短` 不会重复下载。
- 新增 URL 行会继续进入下载流程。

### 3.2 第二阶段：人工剪辑

下载后，人工剪辑文件放入：

```text
视频数据下载缓存/AfterEdit
```

允许放在子目录中，例如：

```text
视频数据下载缓存/AfterEdit/某批次output/*.mp4
```

系统扫描规则：

- 递归扫描 `AfterEdit` 子目录。
- 忽略隐藏文件和隐藏目录。
- 忽略系统生成的回表文件。
- 不依赖上一轮下载任务卡片是否仍存在。

### 3.3 第三阶段：生成 AfterEdit 回表

在 Web UI 中点击扫描或生成回表。

系统会先治理剪辑文件名：

```text
清洗后的原文件名_分辨率P_YYMMDD_秒数.mp4
```

示例：

```text
output1_1080P_260504_000012.mp4
```

文件名规则：

- 原地重命名，不复制文件内容。
- 分辨率和时长来自 `ffprobe`。
- 日期来自文件修改时间 `mtime`。
- 同名冲突时追加 `_02`、`_03` 等后缀。
- 重命名失败时不会进入二阶段处理，需要先解决权限或文件占用问题。

### 3.4 第四阶段：AfterEdit 二阶段处理

使用生成的 `AfterEdit_归档记录表.xlsx` 启动二阶段。

二阶段行为：

- 按 `相对路径` 定位本地剪辑文件。
- 路径必须限制在 `AfterEdit` 目录内，拒绝 `..` 逃逸路径。
- 不强制要求 `来源URL`。
- 按 `文件名` 作为归档文件名基础。
- 打标后只按唯一 `内容题材` 路径归档。

预期状态：

- `已归档`：已完成打标、归档、回表。
- `已下载未归档`：模型有标签结果，但没有唯一可归档的 `内容题材`，需要人工确认归档类目。
- `已跳过：视频过短`：视频短于模型可处理阈值，不算系统失败。
- `打标失败`：模型调用、响应格式或标签结果异常。
- `归档失败`：文件复制或目录写入异常。

## 4. 视频长度要求

真实测试中，模型视频输入对时长有下限。

当前系统规则：

- `< 2 秒`：本地直接标记为 `已跳过：视频过短`，不调用模型。
- `>= 2 秒`：允许进入模型打标。

剪辑建议：

- 正式测试片段建议保留 `>= 3 秒`。
- 2 秒附近的片段容易受编码、帧率、封装时间戳影响，不建议作为稳定测试样本。

已观察到的经验边界：

- 约 `0.3s` 到 `1.8s` 的片段会稳定失败或被跳过。
- 约 `1.9s` 到 `2.5s` 的片段可能可用，但不建议依赖。

## 5. 页面状态说明

Web UI 使用用户语言展示任务阶段。

常见状态：

- `下载中`
- `等待剪辑`
- `等待打标`
- `等待人工确认归档类目`
- `归档成功`
- `已跳过：视频过短`
- `失败`

结果总览应重点看：

- 文件名
- 当前环节
- 归档路径

原始日志只用于调试，不作为业务验收主入口。

## 6. 常见问题定位

### 6.1 只下载了部分文件

优先检查：

- 表格中旧行是否已经有 `已归档`、`已下载待剪辑`、`已下载未归档` 或 `已跳过：视频过短`。
- URL 是否属于当前支持平台。
- 平台 cookies 是否过期。
- 下载失败信息是否提示需要登录、风控或地区限制。

### 6.2 AfterEdit 页面看不到剪辑文件

优先检查：

- 文件是否放在 `视频数据下载缓存/AfterEdit` 下。
- 文件扩展名是否为常见视频格式。
- 是否点击了扫描或生成回表。
- 文件是否是隐藏文件或在隐藏目录中。

当前实现不依赖持续文件系统 watcher；页面加载和用户点击扫描时读取目录快照。

### 6.3 刷新后任务卡片消失

当前任务历史会落盘到：

```text
.runtime-state/tasks.json
```

刷新页面或重启 Web 服务后，最近任务应能恢复。若没有恢复，检查该文件是否被删除，或服务启动目录是否不是项目根目录。

### 6.4 打标失败很多

按顺序排查：

1. 视频是否短于 2 秒。
2. 模型 Preflight 是否通过。
3. API key 或额度是否可用。
4. 模型是否支持视频输入。
5. 模型响应是否能解析为合法标签路径。
6. 标签路径是否存在于当前 taxonomy。

### 6.5 `已下载未归档` 不是失败

该状态表示系统没有拿到唯一可归档的 `内容题材` 路径。

处理方式：

- 人工确认或补充归档类目。
- 后续可在 UI 中增加人工修正入口。

## 7. 验收清单

一轮测试通过至少应满足：

- 下载阶段不会重复处理已完成行。
- 剪辑文件放在 `AfterEdit` 子目录内也能被发现。
- 非标准剪辑文件名会在回表前自动修正。
- `AfterEdit_归档记录表.xlsx` 包含 `相对路径`。
- 二阶段不依赖原始 URL 也能处理本地剪辑文件。
- `< 2 秒` 视频被跳过，不算系统失败。
- 可归档视频写回 `已归档`、标签列、归档路径、归档文件名。
- 页面刷新后能看到最近任务历史。
- 原始日志只用于调试，业务验收看结果总览和表格状态。
