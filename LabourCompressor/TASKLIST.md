## 2. V0.3 执行目标

V0.3 在 V0.2 本地 Web UI 基础上，把人工剪辑前置步骤自动化。用户在本地 Web UI 中完成：

1. 配置平台下载凭证与模型 API
2. 导入任务表格并运行 Preflight
3. 启动下载与自动分割
4. 系统把源视频切为 `3-30s` 片段，最佳区间为 `5-30s`
5. 合法片段进入 `AfterEdit` 并继续视频级打标、回表、归档
6. 问题片段进入 `ProblemClips`，表中标记 `自动分割待处理`
7. 查看结果、失败原因，并导出失败 CSV

V0.3 验收口径：用户无需 CLI 参数即可完成 `表格 -> 下载 -> 自动分割 -> 片段级视频打标 -> 多分支回表 -> 唯一内容题材归档 -> xlsx 总表同步`。

V0.2 作为 `v0.2.0` tag 和 GitHub baseline 保留；关闭自动分割后仍可使用人工 `AfterEdit` 流程。

---

## 3. 强制边界

- 正式视频打标是视频级打标，必须使用模型原生视频理解能力。
- 不默认抽帧；抽帧只允许作为调试、实验或显式降级，并必须在记录中标明。
- 视频送模前必须进入标准压缩缓存：`360p + 原帧率保持 + H.264 650 kbps + AAC 64 kbps + mp4 + 源文件哈希复用`。
- 若压缩后仍超过模型安全阈值，任务明确失败，不静默改为抽帧。
- 下载凭证按平台维护，支持 `cookies.txt` 与 `cookies-from-browser`；系统不承诺自动浏览器登录、自动绕过风控或自动去水印。
- 多平台下载覆盖边界为 `Bilibili / YouTube / 抖音 / TikTok`，实际成功率受平台策略、账号状态、cookies 新鲜度与 `yt-dlp` 支持影响。
- 自动分割依赖 `ffprobe / scenedetect / ffmpeg`，V0.3 不引入完整语义剪辑判断。
- 自动分割问题分类固定为：`无法满足 3-30s`、`导出失败`、`检测结果异常`。
- 任何日志、报告、测试输出不得打印真实 API key、cookies 内容或敏感 token。
- 单文件超过 500 行时，先优化重复、过期、职责混杂内容；优化后仍超限且有清晰职责边界时才拆分。

## 6. Phase C：第一阶段下载

### Task C1：表格驱动下载

- 目标：从用户表读取 URL 并启动下载。
- 规则：跳过 `已归档 / 已下载未归档 / 已下载待剪辑` 行；同一 URL 重跑时以状态列和已有产物为准。
- 交付物：行级任务状态、下载任务记录、失败信息。

### Task C2：平台识别与凭证选择

- 目标：按 URL 自动识别平台并选择凭证。
- 支持范围：`Bilibili / YouTube / 抖音 / TikTok`。
- 凭证优先级：平台级 `cookiesFilePath`、平台级 `cookiesFromBrowser`、全局 cookies 兼容回退。

### Task C3：下载产物标准化

- 目标：下载、合并、重命名后形成可剪辑素材。
- 交付物：标准文件名、下载缓存记录、`AfterEdit` 目录。
- 完成标准：下载完成后回写 `已下载待剪辑`，并暂停流程。

---

## 7. Phase D：AfterEdit 两阶段流程

### Task D1：第一阶段暂停

- 目标：下载完成后不进入自动打标，等待人工剪辑。
- 交付物：`下载缓存目录/AfterEdit`。
- 完成标准：任务状态清楚显示下一步是人工剪辑。

### Task D2：AfterEdit 文件规范

- 目标：约束人工剪辑后的文件名。
- 标准：`原视频标题_视频下载分辨率_下载年月日_视频时长秒数.mp4`。
- 示例：`刷短视频现状_720P_260426_000027.mp4`。
- 允许字符：中文、英文大小写、数字、`_`、文件扩展名中的 `.`。

### Task D3：生成 AfterEdit 表格

- 目标：用户点击后扫描 `AfterEdit` 并生成标准记录表。
- 交付物：`AfterEdit_归档记录表.xlsx`，第一行第一列为 `文件名`。
- 完成标准：生成后自动载入用户表路径。

### Task D4：第二阶段启动校验

- 目标：打标前阻断无效剪辑文件。
- 必查项：文件名规范、重复文件名、表格登记文件是否存在。
- 完成标准：异常项回填失败状态和 `失败信息`，不进入打标。

## 8. Phase E：视频级打标、回表、归档

### Task E1：视频压缩缓存

- 目标：送模前建立可复用压缩缓存。
- 交付物：按源文件哈希复用的 `mp4` 缓存。
- 完成标准：缓存 profile 与 PRD 一致；失败明确记录。

### Task E2：视频级模型打标

- 目标：使用模型原生视频理解能力生成候选标签。
- 交付物：候选标签、模型来源、视频缓存 profile、处理时间。
- 完成标准：候选结果不直接回表或归档。

### Task E3：标签合法化

- 目标：把模型候选裁剪为 taxonomy 合法正式标签。
- 交付物：正式标签记录、标签库版本、决策指纹。
- 完成标准：非法标签不得回表或归档。

### Task E4：多分支回表

- 目标：把正式标签写回用户表与程序内总表。
- 规则：回表保留多分支标签；`内容题材` 唯一化只发生在归档层。
- 完成标准：`一级标签 / 二级标签 / 三级标签 / 四级标签 / 归档路径 / 归档文件名 / 失败信息` 正确写回。

### Task E5：唯一内容题材归档

- 目标：按唯一 `内容题材` 路径归档文件。
- 规则：归档根固定为 `视频数据归档库/内容题材`；非 `内容题材` 分支不参与目录生成。
- 完成标准：每个视频最终只落入一个目录；`xlsx` 中 `归档文件名` 可作为本地文件链接。

## 9. Phase F：失败处理与验收

### Task F1：用户可读失败分类

- 至少包括：缺少平台下载凭证、Cookies 需要重新获取、Cookies 已过期、平台风控拦截、平台请求过频、下载文件重命名失败、未识别到下载产物、合并失败、模型不支持视频输入、视频压缩失败、文件名不合规、标签非法、归档路径冲突。

### Task F2：失败 CSV

- 目标：用户可导出失败项。
- 交付物：行号、URL 或文件名、失败阶段、失败类型、简短原因、下一步建议。

### Task F3：V0.3 端到端验收

- 验收链路：`Web UI 配置 -> Preflight -> 下载 -> 自动分割 -> AfterEdit 片段表 -> 视频级打标 -> 多分支回表 -> 唯一归档 -> 总表同步 -> 问题片段/失败导出`。
- 完成标准：常见失败能定位，成功项可追溯。
