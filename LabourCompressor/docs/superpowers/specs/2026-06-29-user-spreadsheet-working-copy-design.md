# 用户表任务工作副本设计

## 目标

网页端创建用户表任务时，不再直接将用户选择或上传的原表交给流水线。系统在任务启动前于原表同目录创建可写工作副本，后续读取、回写、暂停恢复和续跑全部使用该副本，原表始终不被修改。

本次只治理网页端用户表任务入口。CLI 直接运行、系统生成的 AfterEdit 表和素材目录导入流程保持现状。

## 工作副本规则

输入文件必须是现有流程支持的 `.xlsx` 或 `.csv`。副本与原表位于同一目录，保留原扩展名，文件名格式为：

```text
<规范化原文件名>_任务副本_<YYYYMMDD_HHmmss>_<任务ID前8位>.<扩展名>
```

例如：

```text
测试集O2_任务副本_20260629_163015_a1b2c3d4.xlsx
```

规范化规则：去除扩展名前后的无效空白；文件名中除 Unicode 字母、数字、点、下划线和连字符外的字符替换为 `_`；连续 `_` 合并；空名称使用 `用户表`。时间使用服务器本地时区，任务 ID 使用运行时任务服务已分配 UUID 的前八位。

同名文件已存在时视为冲突并重新生成任务 ID，不覆盖任何既有文件。副本采用排他创建，避免并发任务竞态。

## 创建时序

运行时任务服务增加可选的异步 options 准备钩子。服务先分配任务 ID 和创建时间，再调用准备钩子；网页 composition root 注入用户表副本准备器。准备器执行以下步骤：

1. 校验原表可读、扩展名受支持且父目录可写。
2. 在原表同目录以排他方式复制完整字节内容。
3. 将副本权限设置为当前用户可读写，同时保留合理的组和其他用户读取权限，不继承原表的只读位。
4. 验证副本可读写。
5. 返回仅替换 `spreadsheet` 路径的新任务 options。

准备成功后，任务才进入 `queued` 并持久化。复制或权限校验失败时，API 返回明确错误，任务不会创建，也不会回退到修改原表或系统目录。

准备钩子保持通用，只接收任务 ID、创建时间和原 options，不导入文件系统实现。CLI 未注入该钩子，因此行为不变。

## 数据与界面行为

任务快照中的 `options.spreadsheet` 保存副本路径，确保服务重启、暂停恢复、分阶段续跑和部分回写始终指向同一文件。原表路径不新增数据库字段，也不改变现有 HTTP DTO。

任务创建响应返回的仍是现有任务快照。前端收到响应后，将表格输入框更新为任务快照中的副本路径，并在状态区域提示“已创建任务工作副本”。结果页、事件和后续操作均展示副本路径。

拖拽上传仍先按现有逻辑将文件保存到上传落点；任务创建时再在该落点同目录生成工作副本。文件选择器选择的本地表格直接在其所在目录生成副本。

## 错误与清理

- 原表不可读：返回“用户表不可读取”。
- 原表目录不可写：返回“用户表所在目录不可写，无法创建任务副本”。
- 扩展名不支持：沿用表格格式错误语义。
- 复制、权限设置或副本验证失败：删除本次未完成副本并返回脱敏错误。
- 任务执行失败或取消后保留完整副本，便于查看已回写结果和续跑。
- 系统不自动删除工作副本；其生命周期由用户管理。

错误信息可以包含本地表格路径，但不得包含 cookies、token 或媒体签名地址。

## 测试与验收

- 只读原表能够生成可写副本，原表权限和内容不变。
- 副本位于原表同目录，名称符合规则并包含任务 ID 前八位。
- 流水线和回写收到的是副本路径。
- 两个并发任务生成不同副本且不覆盖。
- 目录不可写或复制失败时不创建任务、不残留半成品。
- 暂停、恢复、服务持久化和阶段续跑复用同一副本。
- CLI、AfterEdit 和素材目录导入行为不变。
- 网页任务响应后表格字段切换为副本路径。

相关单元测试、Web 路由测试、运行时任务服务测试、类型检查和完整回归必须通过。
