# 用户表任务缓存目录设计

## 目标

网页端用户表任务不再使用程序目录中的默认视频下载缓存。任务启动前，系统在用户原表所在目录创建该任务独占的缓存文件夹，后续下载、分割、压缩、AfterEdit、ProblemClips 和本次结果表全部使用该目录。

本次仅改变网页端用户表任务。CLI 显式传入的 `--download-dir`、素材目录导入以及 `resume-cache`/AfterEdit 续跑保持现有路径和行为。

## 路径与命名

缓存目录与用户原表位于同一目录，名称格式为：

```text
<规范化原表名>_视频下载缓存_<任务ID前8位>
```

例如：

```text
/Users/tianyi/Desktop/LS测试文件/测试集O2_视频下载缓存_a1b2c3d4/
```

原表名采用现有工作副本的规范化规则：非法字符替换为 `_`、连续 `_` 合并、去除首尾 `_`，空名称回退为 `用户表`。缓存目录名称以原表为准，不使用已经带有“任务副本”的名称继续嵌套。

同一任务的暂停、恢复、服务重启恢复和阶段续跑复用任务快照中的同一目录。新任务分配新任务 ID，因此创建独立目录。

## 创建时序

扩展现有 `prepareUserSpreadsheetWorkingCopy` 为用户表任务工作区准备器。Orchestrator 分配任务 ID 和创建时间后，准备器执行：

1. 校验原表可读、扩展名受支持且父目录可写。
2. 计算工作副本路径和任务缓存目录路径。
3. 排他创建任务缓存目录，拒绝复用或覆盖同名目录。
4. 排他复制工作副本并设置为当前用户可读写。
5. 返回同时替换 `spreadsheet` 与 `downloadDir` 的任务 options。

准备成功后任务才进入 `queued` 并持久化。目录或副本发生命名冲突时，沿用现有最多三次重新分配任务 ID 的策略。

如果缓存目录创建成功但副本准备失败，只删除本次新建且仍为空的缓存目录。不得递归删除非空目录，不得删除或修改原表。任务执行开始后的失败或取消保留缓存目录和工作副本，便于查看结果和续跑。

`pipelineStage === 'resume-cache'` 时准备器原样返回 options，不创建副本或新缓存目录。

## Preflight 与界面

网页 Preflight 必须检查用户表可读以及原表父目录可写，不再以程序内默认 `downloadDir` 可写作为用户表任务能否启动的依据。其他 CLI 和运行时检查接口保持兼容。

任务创建响应中的 `options.spreadsheet` 和 `options.downloadDir` 是最终路径。前端收到响应后同步更新两个隐藏字段和路径摘要，并显示已创建工作副本及任务缓存目录。此后任何控制、部分回写或续跑操作都使用任务快照中的路径。

## 错误模型

- 父目录不可写：`用户表所在目录不可写，无法创建任务工作区：<目录>`。
- 缓存目录冲突：转换为现有准备冲突，由任务服务重新分配 ID。
- 缓存目录创建失败：任务不创建，返回明确的本地文件系统错误。
- 副本创建失败：清理本次新建的空缓存目录，然后返回原有副本错误。

错误可以包含本地路径，但不得包含 cookies、token 或媒体签名 URL。

## 验收

- 网页用户表任务的 `downloadDir` 位于原表同目录且名称符合规则。
- 只读原表可正常生成可写副本和任务缓存目录。
- 原表内容及权限不变。
- 下载、分割、AfterEdit、ProblemClips 和本次结果表均从新 `downloadDir` 派生。
- 两个任务生成不同缓存目录，冲突不覆盖。
- 副本失败时不残留本次空缓存目录。
- 任务开始后的失败或取消保留目录。
- `resume-cache`、素材目录导入和 CLI 路径不变。
- 前端显示实际缓存路径，Preflight 校验原表父目录可写。
